# 恢复入口可见性与视频原任务手动查询

日期：2026-11-16。

## 问题与行为

用户找不到旧图片失败后的手动下载入口。实际原因是旧记录没有保存成品地址，上一版只对有恢复地址的调用显示按钮；节点标题入口也只有图标。另一次安泰信视频虽已取得任务ID，但原轮询返回failed，原因是`Service is busy or quota reached`，没有手动查询原任务的入口。

本次将图片/视频生成节点入口显示为“调用记录与恢复”，选中或悬停时在标题上方显示，避免窄节点名称被操作按钮挤掉；新生成失败通知增加打开该窗口的按钮。已保存地址的调用显示“重新下载成品（不重新生成）”；无地址的旧失败记录显示原因，并允许补充供应商后台的HTTP(S)成品直链，只下载保存，不提交生成。原“使用结果”由用户点击后采用，恢复不自动覆盖节点输出。

新增`/api/ai/media/calls/query`。对已有ID的安泰信视频提供“重新查询原任务（不重新生成）”，每次只执行一次GET，持久保存查询时间、状态、原因及查询错误标记。查询网络错误时保留上次状态；原生成错误详情不覆盖。查询发现原任务完成时先保存恢复地址，用户再下载。查询仍failed时继续明确显示failed，绝不将“try again later”解释成重新POST生成。

## 实现

- `packages/providers/types.d.ts`增加可选`queryVideoTask`能力；安泰信4.2.2实现固定端点GET，支持Seedance 2.5、Fast、Wan 3.0和MiniMax H3。查询不经过`generateVideo`或`processMedia`。
- `generation.ts`读取当前供应商配置并执行查询，复用宿主脱敏工具；`tasks.ts`与下载共用同一调用锁，阻止同时恢复/查询。新调用预先保存输出目录；旧ID可从既有安泰信错误详情兼容读取。
- `calls/recover.ts`接受可选直链并校验协议及认证信息；下载前先保存补充地址，失败后仍能重试。完整URL不进入调用列表和画布。工作区、输出路径、文件类型和大小校验沿用原实现。
- `nodeSkeleton.vue`展示操作、原任务状态及查询回执；查询/下载进行中禁用重复操作，操作错误不被每3秒列表刷新擦除。两个生成节点通过`callsVisible`模型从失败通知直接打开窗口。

## 验证与边界

已只读查询用户提供的真实任务：HTTP200，`status=failed`，`error.code=GenerationFailed`，原因仍是服务繁忙或配额，未返回视频地址。独立调用新增供应商查询方法、本地新查询接口及Ego Lite网页点击均得到同样结果；网页显示最近查询时间、上游failed及原始繁忙/配额原因，没有提交收费生成。

已完成全仓已有typecheck、Server/Web构建、全部节点开发构建并同步data；最终标题布局调整后再次通过脚手架typecheck与全部节点构建。图片和视频节点build/data文件SHA-256一致。重启本地Server和Vite后，Web、Server及两个生成节点产物均返回HTTP200；`git diff --check`通过。

Ego Lite实测选中图片/视频节点打开“调用记录与恢复”、点击原视频任务查询，以及旧Lite图片失败记录补充用户提供的后台成品链接并下载。2026-11-16 15:38:44那次记录已恢复为成功，保存一个JPEG结果；没有点击“使用结果”，保留当前节点输出。其他旧记录仍可按相同入口补充各自的成品直链。截图位于开发工作区`outputs/diagnostics/manualVideoQuery.png`和`manualImageRecovery.png`；后者捕获到了提示框退场动画，下载成功以记录和本地文件为准。

没有新增测试文件、mock或收费生成。未验证上游失败任务后来变成功、真实查询超时/5xx、URL过期、损坏文件、并发与磁盘失败；Wan/MiniMax/Fast查询未用真实任务验收。查询不能让已失败任务重新运行，不解决上游额度、计价或退款。未知任务ID不能凭空恢复。错误通知入口尚需后续真实失败验收；不为验证而发起收费任务。
