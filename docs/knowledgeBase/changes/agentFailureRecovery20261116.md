# Agent 生成失败后的恢复选择与授权

日期：2026-11-16。基于既有[调用记录与重试下载工具](agentModelCalls20261116.md)，调整 Agent 的提示词与制作 Skill，复用 `askUser` 卡片，不新增接口、配置、依赖或界面。

## 实际行为

- 图片/视频节点本次明确生成失败时，说明节点和已知原因，暂停该节点及依赖链，保留成果；同批失败合并一次选择。
- 提供“我手动处理”及“允许 Agent 查看并尝试下载恢复”。前者引导“节点 → 调用记录与恢复”；后者只覆盖卡片列出的失败调用。跳过、取消、未回答或普通“继续”不授权。自动模式也先询问，预算和重试余量不授权直接重新生成。
- 获批后发现实际节点函数，按本次 `callId` 读取 `node:getModelCalls`，每条最多发起一次 `node:retryDownload`。只用已保存地址或用户提供的对应成品直链；无地址、需要原视频查询时转到现有窗口，不猜链接或调用隐藏接口。
- 恢复失败、取消、超时或结果不明时重读同一调用记录一次后停止。节点等待最多120秒，后端可能仍下载；不自动重复下载或重新生成。已保存的成功结果直接交付。
- 恢复不自动替换节点输出，用户仍需点击“使用结果”；采用并核对实际输出后再继续依赖链。重新生成需另行取得针对失败对象的明确生成授权，并满足原模式范围、总次数、每对象重试余量和其余初次调用预算。
- 等待超时、`waitBudgetExceeded`、启动不确定、未知状态及用户主动取消按真实状态报告，不当作明确生成失败。生成等待与后端下载的内部重试均未调整。

## 关键实现

- `packages/tools/canvas/build.ts`：共享提示词集中维护失败选择、授权范围、按调用恢复与停止条件；工具版本 3.1.1，说明同步至包 readme。
- `apps/server/src/agent/runtime/prompt.ts`：默认系统提示衔接恢复流程，替换自动模式明确失败即可预算内重试的旧规则。保留用户自定义系统提示，不覆盖配置。
- `packages/skills/{canvas,workflow,petShortVideo,longVideoWorkflow}/`：中英文入口及版本同步；workflow 的 `references/canvasExecution.md` 拆分明确失败与超时/取消规则。版本分别为 2.1.5、2.7.8、1.3.5、1.3.4。
- 维护主题：[调用记录与恢复](../nodeModelCalls.md)、[生成等待](../generationWaiting.md)。

这是提示词约束，不是程序级授权锁；工具本身仍按现有权限执行。用户自定义系统提示可能影响行为；本机未配置自定义系统提示，同名工作区 Skill 仍优先于全局安装版本。回滚可恢复本次提示词/Skill、重建工具和服务并同步安装副本，不修改媒体记录或输出。
