| 职责 | 位置 | 维护要点 |
| --- | --- | --- |

| 展示入口 | [nodeSkeleton.vue](../../packages/nodeScaffold/src/nodeSkeleton.vue) | 公共标题栏按钮和对话框读取当前节点的 `modelCalls`；选中或悬停时显示标题操作按钮。 |

| 媒体错误 | [tasks.ts](../../apps/server/src/utils/media/tasks.ts) | 媒体任务失败时在响应消息中附加执行阶段和可识别的错误码。 |

`NodeModelCall` 类型定义在 `nodeAi.ts`，通过 [connection.ts](../../packages/nodeScaffold/src/connection.ts) 的 `NodeData.modelCalls` 存入节点数据。每条包括 `id`、`type`、`providerId`、`modelId`、`startedAt`、`durationMs`、`status` 和 `detail`；新记录排在前面，每个节点最多保留 100 条，单条详情截取前 16000 个字符。成功的媒体调用记录返回结果数量，文本调用记录“模型调用完成”。2026-11-10起图片、视频在请求开始时写入 `running`，结束后更新同一 ID；原生生成节点及局部重绘的记录 ID 与生成编号关联。窗口打开期间显示运行记录的实时已用时间；文本、音频仍在调用结束后写入。自动等待与超时检查见[生成等待维护](generationWaiting.md)。

## 覆盖与限制

- 使用 `useNode()` 提供的 `ai.generate`、`generateImage`、`generateVideo`、`generateAudio` 的节点，以及已绑定节点数据的局部重绘调用，会记录该次封装调用。独立调用 `useNodeAi()` 而未传入节点数据的组件不会自动记入节点；自定义插件或绕过该接口的模型请求也不保证覆盖。
- 一次文本生成可能包含多轮模型请求和工具调用；当前记录对应外层一次生成调用，不是逐轮请求日志。模型列表和价格查询不记入生成记录。
- 取消由传入的取消信号、组件销毁或 `AbortError` 判断；取消只表示客户端调用已取消，不能证明供应商任务或费用已撤销。
- 错误详情取决于服务端和供应商实际返回的消息。媒体任务阶段包括 `prepare`、`provider`、`readResult`、`saveFile`；错误码只在异常链中找到符合格式的值时附加。任务层将错误响应的 `data` 置为 `null`，因此窗口不能恢复被丢弃的结构化详情。
- 记录不主动保存提示词、完整生成请求或媒体字节；URL 成品在下载前保存恢复信息，保存成功后删除恢复字段。上游错误消息可能包含敏感内容，并会写入画布文件，分享前应检查。旧记录中丢失的地址不会自动找回。
- 旧画布记录仍随节点数据复制、保存；新媒体记录独立于画布快照，节点保存首次调用时的画布标识以便画布改名后继续关联记录。完整复制画布时若节点 ID 与该标识也被复制，副本会引用同一批记录；不要把它作为完整审计日志。
- 服务重启后无法重试保存在已退出进程内的终态，磁盘上的未结束记录显示状态未知；已有成品恢复地址仍可重试下载。只有任务 ID 而尚未返回成品的任务，不自动恢复轮询。取消仅表示本地请求取消，不证明供应商已停止。
- 已安装的桌面应用与开发工作区分别使用各自的数据和插件目录；开发构建及服务重启不代表安装版已更新。

## 构建与排查

### Agent 节点工具

- `node:getModelCalls`：参数为可选 `callId`、`offset`、`limit`。列表返回 `calls/total/offset/limit/hasMore`，还有下一页时提供 `nextOffset`；单条详情返回 `call`。列表详情最多 4000 字符，单条最多 16000 字符；Agent 返回值只保留公开字段，隐藏内部恢复信息和详情中的 HTTP(S) 网址。服务端列表读取失败时工具报错，不把旧画布快照冒充实时记录。
- `node:retryDownload`：参数为必填 `callId`、可选 `url`。`canDownload` 为 true 时使用已保存地址；`canSupplyResult` 为 true 时可传用户提供的、无账号密码的 HTTP(S) 成品直链。记录必须属于当前节点及媒体类型。返回 `callId/files/call/outputChanged/alreadySaved/message`；`outputChanged` 为 false，需用户在窗口选择“使用结果”。`alreadySaved` 只说明记录已有保存结果，不额外确认文件仍存在。
- 工具和窗口复用 `nodeAi.ts` 的 `getModelCalls/retryDownload/queryModelCall/retrySaveModelCall`。单次 HTTP 请求固定工作区、原调用画布标识和节点，传递取消信号；窗口仍提供原任务查询和补写终态。新工具由 `useNodeGeneration.ts` 统一注册，音频节点不增加这两个工具。
- 下载仍使用服务端现有同一调用锁和 240 秒恢复上限；节点调用最多等 120 秒。取消、节点卸载或工具超时只停止前端等待，不保证后端下载已停止；必须先重读记录，禁止自动重复下载或重新生成。没有地址、任务状态未知或原任务 failed 都不是重新提交生成的授权。

公共骨架和调用代码会打入各节点 UMD。修改后需要重建受影响的节点；开发模式的构建配置会将产物从 `build/nodes` 同步到本仓库 `data/nodes`，服务端从数据目录加载：

```bash
NODE_ENV=dev bun run --filter './packages/nodes/*' build
```

如修改了服务端任务逻辑，重启对应开发服务；随后刷新开发页面。排查时先确认访问的是目标开发环境，再检查节点是否被选中、标题操作区是否可见，以及 `/api/nodes/files?name=imageGenerationNode` 或对应节点文件是否为新构建。不要假设开发端口或安装版状态长期不变。
