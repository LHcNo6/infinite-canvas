# 宠物搞笑剧情创作

根据用户的宠物图片、性格、想法或已有剧情，创作一条可看懂、可生成的短喜剧。独立调用时只交付文字；由工作流调用时返回完整剧情、表演和资产需求，不操作画布、不消耗算力。沿用用户定稿，仅修改要求的部分。

## 创作

1. 区分真实图片可见的身份特征、用户提供的性格和新提议。图片未实际可读时不要假称看过；影响角色身份时请用户提供可访问素材。默认保留物种、脸型、体型、毛色和明显斑纹，以及自然动物肢体与动作；拟人、服装、讲话按用户要求处理。
2. 用户没有剧情时提出适合这只宠物的原创简单情境；用户有剧情时保留其核心意图。默认竖屏、约 20 秒，最长 30 秒，用户指定优先。按内容调整节奏，不为了凑时长添加无关事件。
3. 以一个清楚的喜剧事件为主：建立观众预期，让宠物主动行动，出现可见的意外结果，留出反应和消化时间。反差、重复变化、误会或余包袱按剧情选择，不强制每项都有。笑点通过画面成立，不依赖解释；不保证观众一定觉得好笑。
4. 每个连续段写起始状态、宠物视线与身体位置、主要动作、道具接触、可见结果、景别和声音，标明前后状态与时间；镜头数量由动作决定。避免一个生成单元承担过多互相依赖的精细动作，必要时简化故事而非虚构模型能力。
5. 默认无需对白，以动作、反应和必要环境声讲故事；用户指定对白、旁白或声音时保留原文、说话者和画内外方式。音乐仅按用户要求或明确创意需要安排，不声称已生成。

## 交付

给出标题、总时长及画幅、宠物身份锚点、简短剧情、按时间排序的可见节拍与镜头、声音、资产清单及用途、生成难点和验收点。已有宠物图优先复用；场景图只有在确实需要独立参考时提出。输入中没有实际图片或模型能力时明确标记，不编造图片内容、引用编号或支持的规格。最终模型提示词由工作流按实际模型和输入方式定稿；独立只需剧本时不强行补充模型提示词。
