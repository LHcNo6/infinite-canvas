# 宠物家庭小糗事短视频制作

让宠物在家里有所图、采取行动、遇到阻碍、改变办法，得到意外结果，结尾回应开头。宠物的选择与现场变化推动故事，短对白表达嘴硬、解释或讨价还价。默认单宠、一个主要场景、中文对白、9:16、480p，按有效内容确定时长，上限 30 秒；用户要求与实际模型能力优先。宠物保留动物结构与自然动作，主人默认画外声音，必要时仅手或脚入画，不要求主人照片。

## 1. 确定交付与本次资料

- 只要主题、剧本、分镜或提示词：只交付该阶段文字，不询问生成模式、不操作画布、不生成媒体。无实际图片也可按标明的假设创作，不假称看过素材。
- 要制作视频：复用已有主题、用户原文与真实素材；开始时确定交互或自动模式，已选不重问。超过 30 秒的完整制作交给长视频流程，不自行拆段。
- 明确采访使用 `petInterviewVideo`，单人口播段子使用相应讲段子技能，明确带货使用带货流程；用户明确指定其他工作流时遵从指定。

每条新视频或重新定稿时，本轮重新读取本技能、所需导演资料及负责模型定稿的技能正文；同一条视频本轮完整读取且仍适用的资料可复用。通过 `skillOperator(action=list)` 发现真实 name、scope、启停与位置，再用返回的 name、scope 读取正文及包内 path；无此工具时按本轮实际技能目录及可用 read 工具读取。目录查询、上一条视频的阅读和源码位置不能代替本次实际读取，不绕过停用状态。

## 2. 导演创作与逐镜预算

先读取实际安装的 `aiPetShortVideoDirector` 主文件。主题/故事读取其 `references/story.md`，表演/分镜读取 `references/direction.md`，生成规划读取 `references/generation.md`，实际审片读取 `references/review.md`。以导演自身 name、scope 读取，不从本技能目录拼接路径。导演只返回成果，不调用本技能回来，也不操作节点或启动生成。必需正文或资料缺失时保留已有成果，暂停依赖步骤并说明缺项。

新创作必须读取本技能的 [三套完整示例](references/mishapExamples.md)；编写完整分镜、生成提示词或修订节奏时必须读取 [预算与定稿指南](references/mishapShotGuide.md)。它们是虚构教学资料，未经生成，不是用户宠物习惯或实际优化执行的证明。

1. 区分用户事实、可见素材观察与创作假设。提取昵称、真实小毛病、喜欢的东西和家庭用语；没有依据的性格标为假设。
2. 未给主题时由导演提出三个不同机制的候选，每项含开头、目标、阻碍、改变办法、结果/回扣、个性化位置和主要难点，推荐一个。主题请求到此交付；完整剧本或制作请求直接展开推荐项，用户要求先选时除外。已有糗事或定稿直接沿用。
3. 写完整逐字对白和必要行动，再按自然时间分镜。每镜至少 4 秒；短句优先同镜多句或完整交流，只有单句自然时长足够才独占对白镜头。每个重要段落新增信息或改变局面，不按一句话一个镜头编排。
4. 中文按约 4–5 字/秒初估，已有音频以真实时长为准，其他语言按自然朗读。逐镜列每句估时、换气/接话、同步动作、必须单独占时的动作、余量用途及交接状态；同时进行的对白与简单动作只计一次。普通接话约 0.2–0.5 秒自然换气；超过约 0.5 秒的无对白区间说明行动、证据或结果的作用。数字是规划参照，不承诺模型精度，不抢话、吞字或机械凑字。
5. 动作镜头写出刺激、明确目标、行动过程、可见变化和结果；自然寻找、掩藏、补救或揭示可占时，转耳、闭嘴或维持姿势不能填时间。每镜保留景别/机位与空间、动物表演、逐字台词/语气/说话人、同步关系及跨镜状态。道具的唯一数量、位置、遮挡、归属转移和终态要连续。
6. 内容不足先合并短句和因果动作，允许代写时补充有效事件，再预算总时长。用户逐字原文不擅自扩写；固定时长、镜头要求或模型能力冲突时指出具体镜号和冲突，交用户选择。正常速度衔接，动作与回扣完成即结束；不用默认 20/30 秒、慢动作或结尾静止补时长。

完整创作成果包括标题、家庭事件与个性化依据、完整对白、逐镜预算、详细表演分镜、开头与结尾关系、参考素材职责、关键道具状态、主要风险与验收点。按交付阶段控制深度，不给主题请求强加全套制作资料。

## 3. 按实际模型定稿

模型未定时可交通用草稿，明确它未经专用定稿。媒体生成和交互模式具体方案授权前，实际模型、版本与输入模式必须确定。

### Seedance 2.5：使用 sd25-pe

通过 `skillOperator(action=list, scope=global)` 找到全局安装的 `sd25-pe`，用返回的 name、`scope=global` 读取当前主文件，避免同名工作区副本覆盖所需专用版；无工具时按本轮全局目录实际位置读取。本流程只调用已安装技能，不自行安装替代品。

SD 的自更新建议服从宿主技能维护权限：默认使用当前可读本地版。只有用户明确授权本次维护及覆盖范围、相关写权限已开启且宿主提供合规更新能力时，才按上游每会话至多一次的规则更新；全局资料维护沿用 skillOperator，不借联网 npx 或其他命令绕过写权限。未授权或缺少能力时记录“本轮未更新，继续使用当前本地版本”，不把未执行称为失败或已更新，也不阻塞可读版本的优化。获准更新后重新读取实际正文和版本，并核对本地语言入口；实际更新失败按上游提示继续可读本地版。仅编辑技能或讨论方案不触发优化或维护。正文缺失、不可读或停用时保留导演稿并暂停 SD 专用定稿；不用通用稿冒充专用优化完成。

传入完整故事契约、逐字对白、逐镜预算及详细分镜、声音人设/画内外归属、实际素材及其职责、关键道具转移和已确认结局，使用其当前生成模板产出一条完整正文。本工作流明确要求按自然内容形成连续整数秒区间，SD 保留这些已给定的创作时间与顺序，不从页面总时长倒造时间格。比例、总时长、分辨率和声音开关单列为节点参数。

**节奏冲突以本流程与用户要求优先**：`sd25-pe` 关于目标更长时放慢动作、反应或停顿的建议不适用于补足本流程时长。时间不匹配先回创作阶段合并、补有效内容或重新预算；用户固定时长和逐字定稿有冲突时交用户选择。专用优化负责组织表达，不改故事、扩写定稿对白或丢弃关键行动。身份参考与硬首帧分别声明，真实绑定沿用平台 `{{ref N}}`，不擅自换成未绑定的上游标签。

SD 成稿后由本流程逐镜核对，不再交 `videoPromptAdapter` 重写；不额外读取第三方专篇代替已要求的 `sd25-pe`。

### 其他实际模型

按实际目录读取 `videoPromptAdapter` 主文件和其匹配确切版本、输入模式的资料；将同样完整的预算与分镜交它定稿。模型改动先重新适配并核对授权，不对其他模型套 SD 规则，不静默切换模型。参考或模型表现资料缺失如实标明，不把缺少质量证据当成接口明确不支持。

### 定稿完成条件

在已有故事/方案中保留完整故事与逐字对白、逐镜预算与详细分镜、模型定稿全文、本轮实际读取的 name/scope/版本字段（如 `version` 或 `skill_version`）/资料路径，以及更新失败、回退和未完成项；不另建重复收据。模型正文只留可提交创作内容，优化记录和参数放正文外。查询目录、历史阅读、教学示例与泛称“已优化”都不算本次完成证据。

逐镜对照内容：事件顺序、逐字对白与声音归属、刺激和反应、动作过程/可见结果、关键证据、道具与跨镜状态、自然接话和结尾全部保留，才可交付定稿或申请生成授权。发现缺项或空等，先按原范围修订；不能只留下“趴着、说一句、看主人”的摘要。

## 4. 画布与生成准备

只在制作请求中操作画布。先读当前画布、可用节点类型与 `getNodeTools` 的真实函数/schema；复用本次已有文本、真实宠物输出及视频节点。必要时创建故事文本、图片生成“宠物主角”和视频生成节点；独立场景参考确有必要时才增加图片节点。不创建商品节点，不将文本连到生成输入。

用户照片优先作身份或起始图，不强制重新生主角。无导入工具时使用节点上传入口，不能凭路径假称已经上传。场景图明确只控制布局/光线还是包含同一宠物，避免多参考变成多只宠物；已有可用输出不重复生成。

用 `node:getConfig` 按实际 schema 查询模型目录（需要时显式 `includeModels`）、当前配置与 `durationResolutionMap`。生图前按计划素材的类型、数量、职责以及时长、画幅、分辨率、声音核对模型声明；尚未生成的图没有真实输出，不能用此时的 `matchingModes` 排除计划的图生视频模式。方案写清待生成节点与参考职责。

素材就绪后读真实端口，以 `connectNodes` 连接宠物及启用的场景图片输出到视频输入；读回边与真实有效输出，按输入端口的有效顺序映射 `{{ref N}}`：`data.referenceOrder` 缺省是正常情况，此时沿用实际有效输入顺序；存在该端口排序时，键为 `encodeURIComponent(JSON.stringify([source, sourceHandle]))`；按排序表构造键到索引的 Map（重复键保留最后索引），未列键取 Map.size，相同排序值保持有效输入原序。不能确认有效顺序时先请用户核对，不猜编号。再查询实际 `matchingModes`，设置并读回输入模式、画幅、最终剧本时长、分辨率与声音。不支持必要条件时保留成果，请用户选择；不静默删参考、声音、缩短或分段。

完整定稿通过真实节点工具写入视频节点，**读回全文**，与已保留的预算及详细分镜逐项核对；检查真实引用与参数，只有内容和技术准备均通过才可启动视频生成；本批必要图片按下节授权先行生成。技术 `preflightCanvas` 不能代替创作复核。首版单次生成完整视频，不自动分段、合成、后期配音或加字幕。负载过高先简化非关键动作，核心因果仍放不下时说明代价交用户选择。

## 5. 授权、执行与恢复

交互模式在任何媒体生成前一次展示本批对象/数量、模型与供应商、规格/视频时长、完整提示词、真实或指定待生成节点参考及职责、声音归属、执行次数和可得报价或“算力消耗未知”，明确同意后执行。待生成素材就绪后还需核对实际输出符合授权方案。

自动模式开始时集中取得本次目标、必要图片规格、视频时长或允许按内容决定的范围、画幅/分辨率/声音、图片和视频供应商/模型或有序候选、总调用上限（含重试）、每对象失败重试上限的明确授权；说明完整提示词在授权后形成，费用不可得时算力消耗未知。范围内自主创作与执行，不逐阶段重复确认；跳过、取消或未回答不授权。预算是提示词约束，不是程序级保护。

每次调用前核对模型、完整正文、参考、参数与剩余次数，留足其他计划对象初次调用预算；用户改动内容、模型或素材时重新核对受影响范围。只生成已授权且缺失的必要图片，记录 `attemptId`、`startedAt`，使用 `node:waitGeneration({attemptId})` 等待；真实素材连线与模式核对、视频正文读回通过后启动一次视频生成并等待该次终态。旧输出或 idle 不证明本次成功。运行中、超时、取消和未知状态不重复生成；重开先查原尝试，关闭或切换画布不保证后台续跑。

明确失败时保留成果，暂停依赖链，按宿主流程提供手动查看记录/重新下载，或授权 Agent 查看本次记录并尝试一次下载恢复的选择。恢复不生成、不自动采用；恢复成功由用户点击“使用结果”并核对。失败后新生成须另获针对该对象的明确授权，自动模式还需满足总次数、对象余量及其他初次调用预算；重试余量本身不授权重生成。

有工具时沿用 `preflightCanvas`、`getProduction`、`updateProduction`、`verifyProduction` 及 revision；批量覆盖前用 `createCanvasSnapshot`，失败停止覆盖。缺工具如实说明，不另造制作系统。

## 6. 成片检查与交付

使用导演审阅方法实际观看并听取完整输出，检查宠物身份/身体结构、真实个性化细节、道具数量与转移、动作因果、中段变化、声音和口型归属、逐字台词、各镜至少 4 秒、接话、无新信息等待和结尾回扣。抽帧或低音量检测只辅助定位，不等于完整看听、精确句间间隔或自动裁剪依据。

报告真实节点与成品路径，区分生成成功、已检查和用户采用，未看未听部分明确列出。方法或读回复核不保证模型准确执行、故事好笑或用户留存；审片建议不授权再次生成。
